# 51. PROMPT COMPILER — EVIDENCE-DRIVEN TUNING

Only change compiler behavior in response to:

real generation failure;
clear semantic omission;
demonstrated model sensitivity;
prompt contradiction;
unnecessary prompt inflation;
loss of canonical meaning;
adapter incompatibility;
observed failure that can reasonably be attributed to prompt representation.

Do NOT tune the compiler based only on subjective preference.

Every material compiler change should identify:

OBSERVED PROBLEM
→ CANONICAL INTENT
→ CURRENT COMPILED REPRESENTATION
→ SUSPECTED FAILURE
→ MINIMAL COMPILER CHANGE
→ REGRESSION TEST
→ RUNTIME RESULT IF AVAILABLE

Do not modify canonical scene semantics merely to make a model accept the prompt.

---

# 52. PROMPT INFORMATION PRIORITY

When prompt length or model sensitivity requires compression, preserve information in approximately this priority:

1. identity/reference locks;
2. causal action order;
3. physical interaction;
4. start/end state;
5. continuity-critical properties;
6. active speaker/dialogue timing;
7. camera intent;
8. environment/lighting anchors;
9. model-sensitive controls;
10. sound intent;
11. secondary aesthetic language.

Remove low-information repetition before removing state-critical meaning.

---

concise.

Do not use maximum verbosity as a default.

# 57. CANONICAL CONTRADICTION GATE

Before any adapter compilation reject contradictions such as:

door OPEN and CLOSED simultaneously;

vehicle PARKED and ACCELERATING simultaneously;

subject OUTSIDE and SEATED simultaneously;

subject approaching an object already held;

night environment with locked golden-hour sunlight;

camera STATIC with mandatory continuous orbit;

speaker A and speaker B owning the same exclusive dialogue turn;

LOCKED wardrobe changing without declared transition;

object ownership changing without transfer;

shot start state contradicting previous shot end state.

Repair canonical state first.

Do not repair contradictions only in prose.
